## 阅读模式（第一步交互改进）

用一个互斥模式选择器代替两个相互依赖的开关。浮窗顶部、托盘和设置使用相同名称：

| 模式 | 划选文字 | 快捷键 / 已启用的鼠标侧键 |
| --- | --- | --- |
| 快捷键查词 | 不自动翻译 | 主动取词 |
| 划选即翻译 | 浮窗显示或隐藏时均自动翻译 | 主动取词 |
| 伴随阅读 | 仅浮窗显示时自动翻译 | 主动取词，可重新打开浮窗 |

保留旧配置字段，兼容现有用户配置，不增加重复保存的模式字段：

```text
auto_popup_on_selection=false                    → 快捷键查词
auto_popup_on_selection=true, only_visible=false → 划选即翻译
auto_popup_on_selection=true, only_visible=true  → 伴随阅读

浮窗 / 托盘选择模式
    → SelectionConfig.set_mode()
    → 保存配置
    → 同步浮窗标签与托盘菜单
    → 按当前暂停状态重建监听器

设置选择模式 → 工作副本 → 保存并应用 → 相同同步流程
                    └ 取消 → 当前模式不变
```

边界规则：改变模式不主动发送翻译请求、不打开隐藏的浮窗、不解除取词暂停。
快捷键查词说明须明确：已启用的鼠标侧键也可以主动取词。
伴随阅读保持现有规则：不通过点击外部或计时自动收起，用户可主动收起。
自动收起的判断须统一，不能因为鼠标移入后移出而改变伴随阅读规则。

架构分工：核心配置负责兼容映射；GUI 共享模式名称与说明；主控制器负责
跨入口同步和监听器生命周期；取词适配器沿用现有布尔参数。

## 翻译方向与切换（第三步交互改进）

浮窗第二行显示“自动检测 → 简体中文”，点击可选择源语言或目标语言。
托盘使用相同语言名称和互斥选项；保留已有自定义语言代码并显示原值。

```text
浮窗 / 托盘切换引擎、源语言或目标语言
    → 控制器使旧请求失效 → 保存配置 → 同步两个入口
    → 浮窗显示且当前原文非空：按新配置重译当前编辑内容
    → 浮窗隐藏或原文为空：仅更新配置
```

重复选择当前值不发送请求。重译开始时停止输入防抖，避免重复请求，并清除
旧译文的复制来源。新请求仍遵循请求标识检查，旧结果不能覆盖新的翻译方向。
GUI 共享语言名称和菜单构造，控制器统一管理配置与重译；工作线程沿用请求快照。
顶部使用两行布局，给翻译方向和取词模式留出空间。

## 引擎状态、失败恢复与输入（第四至第七步）

引擎标识仍保存为原代码；浮窗、托盘和设置使用统一显示名称。配置状态仅描述
本地配置：微软无密钥显示“免配置”，回环地址显示“本地服务”，其他服务按密钥
显示“已配置密钥”或“未配置密钥”，不以此宣称网络连通或密钥有效。

```text
选择已配置引擎 → 同步配置 → 重译可见原文
选择未配置引擎 → 保持当前引擎 → 打开该服务的设置
设置保存 → 重新计算菜单状态；取消 → 当前配置不变

请求失败 → 显示可读错误 + 重试 / 打开当前服务设置
修改原文 → 旧请求失效 → 清除旧复制来源 → 显示“原文已修改，待重新翻译”
    → 自动翻译已开启：600ms 防抖后提交
    → 自动翻译已关闭：回车 / 翻译按钮提交
清空 → 清除结果及状态
```

保留已有用户自动翻译行为，新增输入自动翻译开关默认开启；设置取消不应用。
错误不作为译文复制。重试采用当前编辑原文和当前配置，仍受请求标识保护。
纯核心函数判断密钥需求；GUI 层统一名称与状态；控制器统一切换与设置导航。

打包前修复 Windows SQLite 连接释放和本地唤醒消息读取；使用临时配置验证，
生成独立试用包并保留现有安装与配置。

## 1. 取词与悬浮窗时序 (Timing & Sequence Diagram)

### 收起与请求生命周期（第二步交互改进）

浮窗右上角的 ✕ 表示“收起”，程序仍在托盘运行。点击 ✕、Esc、点击外部
（适用模式）或自动收起均使当前请求失效。收起同时停止输入防抖和收起计时器。
再次通过快捷键或主动查词可以开始新的请求。

```text
选词 / 手动提交 → 分配递增请求标识
    → GUI 线程核对标识 → 显示加载状态，捕获引擎和语言配置
    → 工作线程读取缓存 / 请求翻译
    → GUI 线程再次核对标识 → 显示结果

收起 / 清空 / 修改原文 / 打开新输入框 / 切换引擎或语言 / 保存设置
    → 当前请求标识失效 → 旧加载事件与旧结果都不更新界面

请求 A → 请求 B → B 返回 → 显示 B → A 返回 → 丢弃 A
```

核心层 RequestTracker 只管理标识与线程同步；主控制器持有每次请求的语言、
引擎和缓存开关快照，工作线程不读取界面状态。所有翻译加载和结果展示都通过
控制器的 Qt 信号进入 GUI 线程。检查在 GUI 信号接收时进行，覆盖“结果已入队，
用户随后收起”的边界。原有 HTTP 调用仍为同步调用：失效会阻止后续展示和
尚未开始的请求，但已经发出的网络请求可能继续完成。

```text
用户操作               Selection Adapter         Core Controller            Popup GUI
   │                          │                         │                       │
   │──[鼠标划选文本]─────────>│                         │                       │
   │                          │──[消抖 150ms 校验有效]─>│                       │
   │                          │                         │──[显示 Loading 状态]─>│ (WindowDoesNotAcceptFocus)
   │                          │                         │                       │ 鼠标原焦点保持不丢失
   │                          │                         │──[查本地 SQLite 缓存] │
   │                          │                         │       │ (未命中)      │
   │                          │                         │──[异步请求 API]──────>│
   │                          │                         │       │ (200 OK)      │
   │                          │                         │──[渲染译文/更新高度]─>│ 平滑呈现
   │                          │                         │                       │
   │──[点击空白处或 Esc]───────────────────────────────────────────────────────>│ 隐藏浮窗
```

## 2. 系统级硬核避坑实施细节

### 2.1 悬浮窗防焦点窃取 (Focus Stealing Prevention)
- **问题**：若悬浮窗以普通 Window 形式被映射或创建，操作系统窗口管理器（如 Mutter, Cinnamon Muffin, Windows DWM）会自动将当前键盘焦点转移给浮窗，导致用户打字被硬生生切断。
- **解决方案**：
  - PySide6 窗口标志组合：
    ```python
    self.setWindowFlags(
        Qt.WindowType.ToolTip
        | Qt.WindowType.FramelessWindowHint
        | Qt.WindowType.WindowStaysOnTopHint
        | Qt.WindowType.WindowDoesNotAcceptFocus
    )
    self.setAttribute(Qt.WidgetAttribute.WA_ShowWithoutActivating, True)
    ```
  - 当浮窗需要点击按钮（如“复制结果”）时，点击事件正常响应，但不会强行夺走父级应用的 ActiveFocus。

### 2.2 剪贴板保护与防死锁通道 (Clipboard Preservation & Failsafe)
- 在 Windows 或不支持 Primary Selection 的应用中，划词触发需模拟按键 `Ctrl+C`。
- **操作流程**：
  1. 临时保存用户系统当前剪贴板文本与格式 `old_clipboard = pyperclip.paste()`；
  2. 模拟发送 `Ctrl+C` 并等待剪贴板变化（超时 200ms）；
  3. 获取到新选中的文本；
  4. **异步/延迟恢复原剪贴板内容**，保证用户的复制历史不被划词查询污染。

### 2.3 紧急逃生通道 (Panic Failsafe)
- 全局常驻守护进程必须内置不可屏蔽的强制紧急终止快捷键：
  - 默认：`Ctrl + Alt + Escape`
  - 行为：触发后立即停止所有监听钩子，注销热键，关闭悬浮窗并退出进程。
- 退出钩子绑定：`atexit.register(...)` 与 `signal.signal(signal.SIGINT, ...)`，杜绝崩溃遗留僵尸钩子。
